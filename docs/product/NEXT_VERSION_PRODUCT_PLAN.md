# 开薪 1.5：下一版本轻量产品开发方案

> 版本主题：发薪有仪式，收工有回声。
>
> 文档类型：轻量 PRD + 开发交接文档

## 1. 产品原则

开薪不是专业记账工具。它把工资进度、下班倒计时、愿望和发薪日做成轻量、有情绪价值的日常体验。

- 不新增标签页、后台服务或第三方统计 SDK。
- 不做预算、账单、银行同步、税务、AI 对话、社区、商城或养成游戏。
- 每天的核心流程应在 15 秒内、两次点击内完成。
- 原创角色仅作视觉表达，不取名、不升级，没有故事章节、连续签到或陪伴剧情。
- 会员功能默认使用正常功能名称；用户点击受限能力后，才询问是否前往会员开通页。

产品判断参考：[SalaryClock](https://apps.apple.com/us/app/salaryclock-earnings-timer/id6769226192)、[Finch](https://apps.apple.com/us/app/finch-self-care-pet/id1528595748)、[DailyBean](https://apps.apple.com/us/app/dailybean-simplest-journal/id1553223828)、[1 Second Everyday](https://apps.apple.com/us/app/1-second-everyday-video-diary/id587823548)。取其“轻操作、即时反馈、留下可回看的结果”，不复制复杂养成与内容体系。

## 2. 版本能力

### 发薪日与实际薪资

- 发薪日当天第一次进入 App 自动展示一次全屏彩蛋；首页入口全天保留。
- 当月没有设置日期时，按该月最后一天触发。
- 分享默认隐藏金额，用户可以主动显示。
- 会员可补录任意历史月份；当前月从发薪日起可填，未来月份不可填。
- 实际薪资优先用于月度、年度统计和工资报告。
- 实际薪资只参与同币种统计；修改工资币种后，旧币种记录继续保留但不参与当前统计，用户可按当前币种重新填写替换。
- 入口分工保持单一：薪资设置只管理计算规则；统计页工资总览提供“实际薪资”主入口；发薪日页面提供当月快捷入口。
- 历史页默认从最近月份向前排列，只展示当前月及过去月份，不用未来月份制造待办压力；已填写月份同时显示相对预计薪资的差额。
- 填写面板先展示“当前预计”，输入后即时显示“比预计多/少”，保存后同步刷新月度、年度、工资报告和发薪日金额。
- 页面使用“实际薪资”“填入到账金额”“修改实际薪资”等中性名称，非会员点击后再展示会员确认。

### 收工回执

- 正常下班后首页展示“收下今天”；不自动全屏打断。
- 提前收工或结束加班后直接打开回执流程。
- 用户点击首页卡片，再选择一档今日状态，即生成当日回执。
- 回执包含今日完成度、收入、今日状态、文案语气和愿望进度快照。
- 愿望进度只提供手动更新入口，不自动分配工资。
- 每个本地日期只生成一条回执；再次进入返回同一条。
- 个人中心提供“收工回执”入口，用户可随时重开、分享可见范围内的历史回执。
- 下班通知携带内部路由，点击后直达回执；通知不包含薪资金额。
- 加班中点击下班通知时不打断，结束加班后再打开回执；跨午夜加班的回执归入加班开始的工作日。
- 发薪日彩蛋与收工回执不会同时抢占展示：发薪日优先，关闭后再进入待打开的回执。

### 页面减法

- 首页按上班前、工作中、下班后、发薪日和加班中动态展示卡片。
- 下班后隐藏已归零的倒计时、剩余收入和摸鱼卡；用收工回执承接当天结束状态。
- 统计页以工资总览和工资报告为主；成就压缩为单个入口，完整内容在二级弹层展示。
- 新手设置保持单页，明确“趣味工资进度与收工仪式，不做工资或税务核算”。

### 愿望（轻量保留）

- 只保留添加愿望、设为聚焦、手动更新进度、暂停、完成和完成照片。
- 不再提供微光、未来帧、章节、角色命名、互动养成或陪伴剧情；愿望进度不与工资自动联动。
- 旧版工作折算进度会迁移成手动进度；旧剧情字段只读兼容一次，后续保存不再写回。

## 3. 数据、会员与隐私

- `ClosingCapsule` 是兼容旧数据的内部名称，界面统一称“收工回执”。
- 回执新增可选 `wishID`、`wishTitle` 与币种快照；旧数据缺少字段时正常解码，新记录切换工资币种后仍按生成时币种展示。
- 本地和 iCloud 始终最多保存 400 条回执。免费用户展示最近 7 条，会员展示全部历史。
- 旧版故事相关字段可被解码但不再编码；升级不会清空愿望、工资或回执数据。
- 免费能力：每日回执、三档状态、基础语气、最近 7 条记录、隐藏金额分享。
- 会员能力：完整回执历史、额外语气、实际薪资、高级工资报告及既有会员能力。
- 全局金额隐私开启时，发薪日、回执界面及其分享内容均强制隐藏金额。
- 会员弹窗统一使用“这是会员功能，是否前往会员开通页？”；StoreKit 商品标识和内部 `Pro` 类型保持兼容。

## 4. 交互状态

| 场景 | 行为 |
| --- | --- |
| 工作中 | 展示实时收入、进度、倒计时、剩余收入与必要操作 |
| 正常下班 | 首页展示“收下今天”，用户主动打开 |
| 提前收工 | 确认后打开收工回执 |
| 加班中 | 不展示收工回执入口 |
| 结束加班 | 保存加班记录后打开收工回执 |
| 发薪日首次打开 | 自动展示一次发薪彩蛋 |
| 发薪日全天 | 首页入口一直可用，可重复打开与分享 |
| 跨日未完成 | 不追讨、不补签、不影响下一天 |
| 下班后跨零点 | 倒计时改为柔和的“下次上班”；上班前仍保留品牌标题、收入主卡、进度概览、今天还可赚和摸鱼入口，不把首页简化成单张倒计时；休息日或加班中不误切换倒计时 |
| 非会员点击受限项 | 先展示统一会员确认，再由用户决定是否进入开通页 |

通知遵循 [Apple Notifications HIG](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)；Live Activity 保持简洁并避免敏感金额，遵循 [Apple Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)。

## 5. 验收标准

- 发薪日自动彩蛋每天最多一次，首页入口全天有效。
- 回执在正常下班、提前收工、结束加班、跨日和时区变化下状态正确。
- 同一天重复完成不新增记录；非会员第 8 条以前的数据仍被保存。
- 非会员页面静态状态不出现 `PRO` 或锁定角标；受限操作点击后才出现会员提示。
- 实际薪资新增、修改、删除后，月度、年度、报告和发薪日金额同步更新。
- 薪资设置页不出现实际薪资管理；统计页和发薪日入口可抵达同一份月份记录，重复进入不会产生重复记录。
- 实际薪资历史按最近月份优先展示，当前年不出现未来月份；填写和修改状态均明确展示预计金额与差额。
- 切换工资币种后，旧币种实际薪资不被错误换符号或计入新币种合计，历史记录仍可重新填写。
- 简体中文、繁体中文、英语、日语、韩语均有完整文案。
- 四套主题、Dynamic Type、VoiceOver、减少动态效果和金额隐私模式可用。
- 单元测试覆盖迁移、幂等、历史展示上限、通知路由、会员门控和金额隐私；完整构建与截图回归通过。

## 6. 后续候选

只有在收工回执使用稳定后，再评估自动生成“本周收工回声”拼图。本版本不预建数据结构、不增加入口。
